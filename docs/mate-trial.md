# Private mate trial

Open `/eq-fit/?trial=1#invite=PRIVATE_INVITE`. The invite is a random 256-bit bearer capability; never commit or log the full URL. Seven-day expiry and 20 total requests are enforced by an atomic server-side claim. Requests without a valid invitation fail before Garmin is contacted. The invitation hash and counter are service-only and RLS-protected; neither anon nor authenticated roles can read or claim invites.

Paste a Garmin **Personal API key** and submit. The stateless edge importer exchanges it with Garmin, retrieves the preceding 90 days of activity summaries, and returns normalized running rows by default; the current client requests strength and cardio activity summaries as well with `training: true`. Fixed Garmin endpoints, no redirects, 45-second deadline, 10-page bound (1,000 activities of all types); incomplete downloads fail without returning partial rows. Neither credentials, tokens, nor activity data are written to the server database or logged by application code.

The entry form and Today dashboard offer Running, Strength + cardio, and All training focus choices. Focus is stored per local database; the dashboard classifies Cardio separately from Strength Training without changing the owner’s legacy mapping. Garmin summary imports do not supply sets or reps. Linked activities and workouts count once; missing durations stay unknown.

Trial data goes to a separate IndexedDB database whose name derives from a SHA-256 key fingerprint. The normal `recomp` database and private owner sign-in are never used in trial mode. Each key has separate browser storage. Keys are cleared from the field when submitted and not persisted. Reload and paste the same key to refresh. Stable Garmin IDs make repeat imports idempotent; absent records are retained. Changing a key opens a new trial store. A trial has no account, automatic/background sync, or cloud backup; local backup remains available through More. Deleting browser storage removes the local trial data. Expiry blocks future imports but does not delete downloaded records.

Verification: unit tests cover unit normalization, unknown values, fixed destinations, invite requirement, sanitized upstream errors, pagination failures, credential-free responses and separate database names. Hosted SQL asserts expiry, unknown invite rejection, and the 20-request cap. Live checks confirm missing invite is rejected and an invited invalid key is rejected by Garmin. Successful real-key import remains a participant verification step; do not claim it has been exercised until then.

Security advisors show service-only tables have no client RLS policies intentionally; client grants are revoked. Existing project warning: leaked password protection remains disabled (this trial does not create passwords). Remediation: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

Zero matching Garmin activities is a successful empty import, not a CSV error. The dashboard still opens for manual logging. Network, local storage and import failures have distinct messages.
